BASE UTILIZADA
Sua versão: auto-shine.zip.
Versão do colega: auto-shine 2.zip.
A integração foi feita sobre a sua versão. Não foi usada a pasta do colega
para substituir o projeto inteiro.

COMO ABRIR E EXECUTAR
1. Guarde sua pasta atual como backup e extraia este ZIP em uma NOVA pasta.
2. Copie o arquivo .env da SUA pasta atual para a pasta auto-shine extraída,
   ao lado de package.json. As configurações do colega não foram importadas.
3. Abra a pasta extraída no VS Code. No terminal dessa pasta, execute:

   npm ci
   npx prisma generate
   npx prisma migrate deploy
   npm run check
   npm start

4. Abra o endereço mostrado no terminal. A porta padrão continua sendo 3000,
   a menos que seu .env defina outra porta.
5. Entre com uma conta de CLIENTE e abra o menu com seu nome > Meu Perfil.
6. Use o botão de sol/lua para alternar o tema. O perfil também possui esse
   controle em Preferências. A escolha é mantida ao navegar e recarregar.

BANCO DE DADOS
O projeto continua usando PostgreSQL, como sua versão original.
O DATABASE_URL do seu .env deve apontar para seu banco existente.
As novas migrações adicionam fotoPerfilUrl em Usuario e criam EnderecoUsuario.
As migrações anteriores e os campos de detalhes de serviços foram mantidos.
Faça backup do banco antes de aplicar migrações em um ambiente com dados reais.
Não execute prisma migrate reset: ele não é necessário para esta integração.
Não é necessário executar seed para integrar o perfil.
Se migrate deploy informar erro, pare nessa etapa e confira a mensagem antes
de iniciar o servidor. Não use reset como solução automática.

- Tema claro/escuro baseado no trabalho do colega, adaptado também à sua home,

AJUSTES NECESSÁRIOS NA INTEGRAÇÃO
- O perfil do colega continha o modelo de endereços, mas faltava a migração SQL
  dessa tabela. A migração foi acrescentada.
- O histórico do colega contava endereços como serviços. Agora usa agendamentos,
  conta somente status finalizado e mostra o último agendamento criado.
- Os controles de tema do cabeçalho e do perfil agora ficam sincronizados.
- Contas sem senha (login social) recebem explicação na seção Segurança.
- Foram removidos apenas os invólucros de cabeçalho duplicados de mapa.html e
  servicos.html para permitir posicionar corretamente os novos controles.
- O menu da conta usa texto escapado pelo DOM, fecha com Escape e não acumula
  elementos após salvar dados pessoais.
- O seletor de tema é aplicado antes do conteúdo da página ser exibido.
- Em larguras intermediárias, os links do cabeçalho passam para uma segunda
  linha para não sobrepor o botão de tema e o menu da conta.

LIMITES DA VALIDAÇÃO
O banco real não foi conectado e as novas migrações não foram executadas nele.
Upload real/Cloudinary, Google OAuth, envio de e-mail e mapas externos não foram
validados contra serviços reais. Os testes visuais bloquearam fontes e recursos
externos, portanto a tipografia nas capturas usa fontes alternativas.
A home mantém a implementação mobile anterior, inclusive o botão de menu com
alerta demonstrativo; esta integração não reimplementa esse menu nem o layout
original do carro, que pode ultrapassar a largura em telas pequenas.
